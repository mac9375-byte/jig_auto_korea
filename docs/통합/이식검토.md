# 이식 검토 — jigauto 형상 분류 → app.py (shapely)

작성 2026-11-17 · 대상: 전부 layer `0` 인 도면에서 외곽/부품/홀 역할을 형상으로 구분하는 전처리

## 1. 결론 먼저

| 항목 | 판정 |
|---|---|
기하 연산 이식 가능성 | ✅ **전부 1:1 대응**. cadquery 고유 기능(솔리드 불리언)을 쓰지 않는다 |
핵심 알고리즘 이식 | ✅ `_chains` union-find 는 **순수 파이썬** — 그대로 복사 가능 |
실데이터 외곽 추출 | ✅ **100% 작동 확인** (아래 3절) |
실데이터 부품/핀 추출 | ⚠️ **복원율 낮음** — 규칙이 실도면에서 과도하게 보수적 |
진짜 검증 대상 확보 | ⛔ **없음** — "전부 layer 0 인 제품 도면"은 DWG 안에 있고 ODA 미설치로 못 읽음 |

**이식 자체는 어렵지 않다. 위험은 이식이 아니라 "닫힌 루프 복원율"에 있다.**

## 2. cadquery → shapely 대응 (전수 확인)

| jigauto (cadquery) | shapely/ezdxf 대응 | 비고 |
|---|---|---|
`cq.Edge` (LINE/ARC/CIRCLE) | `ezdxf.path.make_path(e).flattening(f)` → `LineString` | app.py 에 `ezpath` 이미 import |
`_chains` union-find | 그대로 | **cadquery 무관, 순수 파이썬** |
`cq.Wire.assembleEdges` + `Face.makeFromWires` | `shapely.ops.polygonize` | app.py 에 `polygonize` 이미 import |
`face.Area()` | `polygon.area` | 1:1 |
`wire.BoundingBox()` | `polygon.bounds` | 1:1 |
`a.face.intersect(b.face).Area()` | `a.intersection(b).area` | 1:1 |
`_is_rect` | `abs(area - bbox면적) <= tol` | 1:1 |
`geomType()=="CIRCLE"` / `arcCenter()` / `radius()` | ezdxf CIRCLE 엔티티에서 직접 | 더 간단해짐 |
`_to_jig` 미러 변환 | `shapely.affinity.scale(xfact=-1)` | app.py 에 `affinity` 이미 import |
`_sym_diff` (Top 뷰 대조) | `a.symmetric_difference(b).area` | 1:1 |

→ **새 의존성 0개.** app.py 가 이미 import 한 것만으로 된다.

## 3. 실데이터 spike 결과

`base_jig_templates/tape_jig_1.dxf` (실제 한국성전 도면, 1,759 엔티티 중 1,303개가 layer `0`)
를 **전부 layer 0 으로 평탄화**한 뒤 shapely 파이프라인을 돌렸다.

```
입력 선분 1,501 → 닫힌 루프 96 덩어리 / 열린 덩어리 1,132
유효 폴리곤 90 → 테두리 제거 90 → 최상위(외곽 후보) 41
면적 1위: 90.00 x 120.00  ← 담당자 PLAN.md 의 "외곽 후보: 90.000 x 120.000 mm" 와 일치
원 35개, 지름 3.5 (8개) ← 도면 MTEXT "4-%%C3.5 THRU" 와 부합
```

**외곽을 레이어 이름 없이 형상만으로 정확히 찾아냈다.** 담당자가 화면에서 손으로 고른 값과
같은 값이 자동으로 나온다.

### 복원율을 해석할 때 주의

0% 가 전부 결함은 아니다. `HIDDEN`·`Center`·`BATANG` 은 **안 잡히는 것이 올바른 동작**이다.
`PIN` 8.3% 도 결함으로 단정할 수 없다 — 치구 설계 관리 Sheet(r11)에 "수대 양사이드 센터에
**5.02 반홀** 적용" 이 있고, 반홀은 원래 열린 호다. spike 의 원 지름 분포에 5.54/4.55 가
섞여 있는 것도 이와 관련될 수 있다. **개체별 확인이 필요하며 지금 단정하지 않는다.**

확실한 문제는 하나다: **`layer 0` 의 1,072개 중 34개만 복원된다(3.2%).** 이 도면에서는
layer 0 이 주로 표제란·주서라서 큰 문제가 아니지만, **사용자가 말한 "외곽·부품 구분 없이
전부 layer 0 인 제품 도면"에서는 부품 형상이 layer 0 에 있다.** 그 경우 3.2% 는 치명적이다.

## 4. 이식 방식 — 전처리기가 역할 레이어를 입힌다

app.py 의 역할 지정은 **레이어 이름** 기반이다 (`app.py:2446-2450` 의 `multiselect`,
`parse_cad(dxf, layers, ...)`). 그래서 app.py 내부를 고치지 않고 붙일 수 있다.

```
고객 DXF/DWG  →  [전처리기]  →  역할 레이어가 입혀진 DXF  →  app.py (기존 흐름 그대로)
  전부 layer 0      형상 분류      AUTO_OUTLINE / AUTO_COMPONENT / AUTO_HOLE / AUTO_BORDER
```

이 방식의 이점:

- **app.py 코드 변경 0줄.** 사용자는 기존 화면에서 `AUTO_OUTLINE` 을 고르면 된다
- 전처리기를 **단독으로 테스트**할 수 있다 (app.py·streamlit 없이)
- 출력이 DXF 라 **사용자가 AutoCAD 에서 분류 결과를 눈으로 검증**할 수 있다
- "모호하면 중단" 정책을 유지한다 — 전처리기가 거부하면 사용자가 기존 수동 선택으로 간다
- jigauto 와 **같은 전처리기를 공유**할 수 있다 (jigauto 는 PcbModel 로, app.py 는 레이어로)

대안(app.py 내부를 geometry 주입 가능하게 리팩터)은 2,545줄 단일 파일을 건드려야 하고
AGENTS.md 의 "기존 단일 파일 구조 유지, 최소 변경" 과 충돌한다. **채택하지 않는다.**

## 5. 단계 (제안)

| 단계 | 내용 | 검증 |
|---|---|---|
P1 | 전처리기 골격: 읽기 → 체인 → 폴리곤 → 테두리 제거 → 포함관계 | spike 를 모듈로 정리, tape_jig_1 외곽 90x120 재현 |
P2 | 역할 판정: 외곽/홀/부품/테두리 + 모호 시 중단 | 평탄화 전 레이어를 정답으로 복원율 측정, 기준선 기록 |
P3 | 복원율 개선: 열린 덩어리 처리 (허용 공차, 끊긴 목 잇기) | 복원율이 P2 기준선보다 올라가고 오탐이 늘지 않음 |
P4 | 역할 레이어 DXF 출력 | app.py 가 그 DXF 를 읽어 기존 흐름으로 배열까지 통과 |
P5 | 실제 전부-layer-0 제품 도면으로 검증 | **ODA 설치 후** DWG 변환해 확인 |

P3 가 실질 난관이다. P1·P2 는 spike 로 이미 실현성이 확인됐다.
